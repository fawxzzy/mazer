- WHAT changed: the drawn play trail is the path the player actually walked (`src/legacy-runtime/legacyWalkedTrail.ts`, new), built from the scene's move history `this.trail` (one tile per accepted move). Stepping onto the tile the trail came from (its second-last tile) unwrites the last tile; any other step writes, even onto a tile the trail already covers, so loops and self-crossings keep both passes; a repeated tile changes nothing. MenuScene's `computeLegacyPlayPerfectPathTrail` now returns `resolveLegacyWalkedTrail(this.trail, this.player)` (one line plus the import and comment); the memo (`trailPerfectPathCache.ts`), the glide head (`trailHeadPath.ts`), wrap splitting (`navigationCoreTrail.ts`) and the redraw gate are unchanged. Guide trail row: "Star dust marks your route; step back to wipe it. Reduced motion in Settings calms it." (90-character cap).
- WHY it changed: Zac, 2026-11-25: "as the player moves and the trail spawns it changes its placement based on the shortest path to the player, we should rework it to stay stuck to the path the player took and only unwrite itself if the player travels backwards along the path ... levels with ways to go in a circle over top of ones own path could cause issues." The old trail was the shortest route over the visited tiles, so on a maze with loops it re-routed through the shorter side.
- Rule: a trail that represents where the player went must be derived from the move history step by step (a stack: pop on stepping back to the previous tile, push otherwise), never from a path search over the visited set, which forgets order and direction.
- Edge cases (all follow from it being a pure function of `this.trail`): new level, reset, restart, pause-reset to the player's tile, resumed run (its saved history) and preview levels replace the history and so the trail; the menu demo walker's trail is drawn through the same resolver from its raw walk, so its dead-end backtracks now unwrite the way a player's do (it used to show the shortest route too); wrap crossings stay non-adjacent pairs and are split as before; stepping back across a wrap pops as any step back. Trail Fade is off in the game (`TRAIL_TAIL_FADE = false`); if it is turned back on it keeps only the newest 16 moves, so stepping back past the oldest kept move would write instead of unwriting.
- Evidence: `tests/reset/legacy-walked-trail.test.ts` (16 tests: straight, backtrack, dead end, repeat, empty, loop closed and lapped, backing out of a loop, plus-crossing, step back at a crossing, shortest-route contrast, resets, Trail Fade with real `advanceLegacyPlayStep` moves, scene wiring); drift test pins the Guide copy and the wiring.
