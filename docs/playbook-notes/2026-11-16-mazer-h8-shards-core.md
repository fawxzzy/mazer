# 2026-11-16 Mazer slice H8 (core): shards, locked star, tail route target

- WHAT changed: new pure modules `src/mazer-core/hazards/shardSolvability.ts` and `src/mazer-core/hazards/shards.ts` (exported from the hazards barrel), an independent brute-force shard oracle `tests/core/hazards/shardOracle.ts`, tests `tests/core/hazards/shards.test.ts`, and the runway assert `scripts/analysis/shard-runway.ts`.
- WHY: roadmap H8 (cards PROG-005/019). Past geometry saturation the only forever lever is route length; shards make it rise every level without touching geometry.
- Rule: the route target is strict from saturation: `SHARD_ROUTE_BASE (160) + SHARD_ROUTE_STEP (2) * (level - saturation)`, band `[target, target + SHARD_ROUTE_BAND (1)]`. STEP > BAND keeps bands disjoint, so every realized route beats the previous level's even though grid parity fixes a static tour's parity. Before saturation the plan is non-strict (no target).
- Rule: the star is locked (plain floor) until all shards are collected; a shard counts only when it is the next one. Shard legs never cross a Sentry rail (eligible cells exclude rail cells and cells cut off by them).
- Rule: `computeShardLayer` returning `failed` is the caller's cue to reject the base and try the next seed (contract reject-and-try-next-base loop), capped by `GEOMETRY_BUDGET_BASE_CANDIDATES` (24).
