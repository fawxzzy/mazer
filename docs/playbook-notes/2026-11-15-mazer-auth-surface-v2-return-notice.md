# 2026-11-15 Auth Surface v2 follow-up (Wave 5C): host return notice, safe error constant on the matrix, address-bar pins

- WHAT changed: boot reads the account host's closed `?notice=expired|unavailable` key once (`src/legacy-runtime/legacyAuthReturnNotice.ts`), strips it from the address bar with `history.replaceState` right after the OAuth callback scrub, records it as the held boot failure (`expired` -> `signin.callback`, `unavailable` -> `signin.unavailable`) so the signed-out status box shows that matrix line, and tells the automatic hand-off to stay (`return-notice`). `MAZER_OAUTH_SAFE_ERROR_MESSAGE` is now `AUTH_SURFACE_MESSAGES['signin.unavailable']`, so the temporary status-box mapping from PR-A2 is gone. New regression pins: the callback scrub leaves no `code`/`state`/`error`/`error_description` in the address bar and runs before the first `await`; `index.html` keeps `<meta name="referrer" content="no-referrer">`; the CSP posture (none declared) does not change by accident.
- WHY it changed: FawxzzyWeb PR 181 sends stopped authorizations back to Mazer with that key instead of a portal dead end; without this Mazer showed its plain sign-in with no reason, and the automatic hand-off could leave for the host again (a manual Sign in records no attempt, so the loop guard would not stop it).
- Rule: a notice key from another app is a closed set read once at boot, stripped like callback material, and never treated as a callback; unknown values show nothing.
- Failure Mode: a return that carries a stop reason but is not a callback is invisible to the `oauth-callback` stay reason; it needs its own stay reason or the boot redirects straight back to the host that just refused.
- Decision: the copy matrix has no "expired" sign-in row; `expired` (expired, invalid or other-account) shows `signin.callback` ("We could not finish signing you in. Sign in again.") rather than `mazer.timeout`, which would be wrong for the other-account and invalid cases.
