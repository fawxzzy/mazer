- WHAT changed: MAZER-PERF-017 follow-up, the board-layer exact copy (option A of the board cost options page, #705), built so nothing visible changes. New `src/render/boardLayerFrameCache.ts`, installed by `BoardTileLayer` on its own image (a few lines in `src/render/boardTileLayer.ts`, a `readCanvasContextResolution` helper in `src/boot/canvasResolution.ts`; MenuScene is untouched). When the board image's draw inputs hold still for 2 frames (board texture content version, image and parent-container transforms, camera, alphas, canvas size, resolution, frame size), Phaser's own `renderCanvas` runs ONCE with `renderer.currentContext` swapped to an offscreen layer the size of the game canvas. Every following frame is a 1:1 `drawImage(layer, 0, 0)` at device (0, 0) on the game context. Anything that changes (build/teardown reveal, zoom, resize, theme rebake, scene restart) draws through Phaser as before and refills once still. Not cached: non-normal blend, crop, mask, zero alpha. Kill switch `?boardLayerCache=0`; runtime `boardTileLayer.frameCache.setEnabled(bool)`; `frameCache.stats` = hits / fills / passes. The plain 1:1 blit (`exactImageBlit.ts`, option A as drawn on the page) stays dormant: it is not the same picture.
- WHY it changed: under `roundPixels: true` Phaser grows every Image's destination by 0.5 css px (batchSprite), so the baked board (about 2.75 Mpx at level 300, 3x) is resampled every frame although it did not change; 30 ms a frame on WebKit (2026-11-24-mazer-board-tile-cost-options.md). A plain 1:1 blit of the texture shifts tile edges by up to 1.5 device px at the far edge (about 8% of pixels differ), which Zac rejects. Resampling once and copying the result keeps today's pixels.
- Rule: a draw-cache must reproduce the old draw's result, not a nearby cheaper one; get it by letting the old draw run once into the cache (swap the renderer's context), never by re-implementing it. Never `setTransform(1,0,0,1,0,0)` on a Mazer context: `canvasResolution.ts` patches `setTransform` to multiply by the resolution; use `resetTransform`, and patch the offscreen layer's context the same way. Every input of the draw must be in the key; a new animated input (a board that moves, a tint) must be added to the key before it ships.
