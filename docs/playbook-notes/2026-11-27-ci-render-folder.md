# 2026-11-27 - CI runs the whole tests/render folder

- WHAT changed:
  - `.github/workflows/verify.yml` (job "TypeScript, contracts, and build") has a new step, "Verify the whole tests/render folder", that runs every file in `tests/render` (90 test files, 2170 tests) with the thread pool and 4 workers, the same settings as the "whole tests/reset folder" step from PR #727. No exclusions: every file passes on a clean main under the thread pool, and none calls `process.chdir` or reads a local-only fixture.
  - The 19 `tests/render/*` files that the step "Verify intro timeline, edge markers, tile bake, and lifecycle analyzer contracts" listed by name were removed from it so they do not run twice; that step is renamed "Verify lifecycle analyzer and MazeV2 adapter contracts" because only `tests/visual/maze-lifecycle-analysis.test.mjs` and `tests/mazeV2/adapters.test.ts` remain in it.
  - `playbook.config.json`: `tests/render/**` added to the `covered` list of `requireTestRegistration`, next to `tests/reset/**`, so a new render test needs no registration.
  - Header comments in `scripts/verify/navigation-core-required-tests.mjs`, `teleport-required-tests.mjs` and `world-identity-required-tests.mjs` no longer say CI names `tests/render` files by file. The measured-baseline and shared-account-oauth headers never mentioned `tests/render` and are unchanged. No code or list entry changed.
- WHY it changed:
  - CI never calls `npm test`; it listed 28 `tests/render` files by name (counting the required-coverage lists) out of 90, so 62 render files never ran in CI and a broken render test could merge green. PRs touching `src/render` went red on first push 13 of 59 times, mostly on failing tests. Zac approved this change on 2026-11-27.
- Rule: a test folder that `npm test` or a required list already treats as a unit is run by CI as a folder, not as a hand-kept file list; any file left out is excluded by name in the workflow with the reason next to it. A comment that describes CI must match `verify.yml` in the same change.
- Duplicates left on purpose: 9 `tests/render` files named in the Navigation Core (4), Teleport (4) and World Identity (1) required-coverage lists now run in both their dedicated step and the folder step (about 5 s of work). Those steps fail loudly when a listed file goes missing and the local `npm run verify` runner imports the same lists, so removing the entries is not clearly safe. `npm test` / `run-test-verify.mjs` still name `tests/render` files by name locally (`package.json` is not edited here); the comment there that `palette.test.ts` fails on a clean main is stale (it passes) and is left for a separate local-runner change.
- Evidence: on unchanged `origin/main` (52d6d94f), `vitest run tests/render --pool=threads --maxWorkers=4` gave 90 files, 2170 passed, 0 failed, 74.6 s. Verify job duration before this change: about 11.5 min. After: see the pull request. The pull request's own Verify log is the CI proof (it prints the file and test counts for `tests/render`).
- Status: source only; CI change, no app behaviour change, no deploy needed.
