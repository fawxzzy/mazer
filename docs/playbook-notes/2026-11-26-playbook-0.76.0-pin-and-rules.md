# 2026-11-26 - Pin Playbook 0.76.0 and switch on two verify rules

- WHAT changed:
  - The pinned Playbook CLI moved from 0.75.0 to 0.76.0 (version, GitHub release fallback tarball URL and its SHA-256 `185eb597d90a485000bea02fc5c7e58171e97cd7ee4308dac2da8b522f963a81`).
  - `playbook.config.json` switches on `generatedFilesInSync` for the owner export: a change to `config/mazer-owner-work-registry.json`, `docs/current-truth.md`, `docs/roadmap.md`, `docs/mobile-plan.md` or `scripts/export-project-board-owner.mjs` must come with a regenerated `exports/mazer.project-board.owner-export.v1.json` (`npm run project-board:owner-export`).
  - `playbook.config.json` switches on `requireTestRegistration`: a NEW `tests/**/*.test.ts` or `tests/**/*.test.mjs` file must be named in a workflow under `.github/workflows`, in a list under `scripts/verify`, or in `package.json`, unless it sits in a folder that a runner already takes whole.
- WHY it changed:
  - The stale owner export was the top deterministic first-push CI failure in this repo (the "Owner export" job). The export records a hash of each of those five sources, so any change to one of them makes the committed export stale. Playbook verify now catches that before a pull request is opened instead of CI catching it after.
  - Reviews repeatedly asked for new test suites to be registered in the required-test lists (for example PR 442 and PR 458); a test nobody lists is never run and can rot.
- Rule:
  - Only exact generator pairs go into `generatedFilesInSync`. The work report (`docs/ops/MAZER-WORK-REPORT.*`) is left out until its full input list is confirmed.
  - `covered` lists folders that a runner takes whole: `tests/core`, `tests/cosmetics`, `tests/tutorial`, `tests/architecture`, `tests/brand`, `tests/legacy-runtime` (CI, `verify.yml`) and `tests/reset` (the local spine: `npm test` and `scripts/verify/run-test-verify.mjs`). A new test anywhere else must be named in a list.
  - Only added test files are checked. Tests that already exist unlisted are not flagged.
- Known gap (not changed here): CI names only some `tests/reset` files; the rest run in the local spine only. `tests/reset` counts as covered because the local spine takes the folder.
- Evidence: scratch runs of Playbook verify 0.76.0 on this branch (both rules fail on a seeded violation and pass once it is fixed), and this pull request's Playbook verify job.
- Status: source only; tooling pin and verify configuration, no app behavior change, no deploy needed.
