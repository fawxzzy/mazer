# 2026-11-26 - CI runs the whole tests/reset folder

- WHAT changed: `.github/workflows/verify.yml` (job "TypeScript, contracts, and build") has a new step, "Verify the whole tests/reset folder", that runs every file in `tests/reset` (218 test files, about 2,930 tests) with the thread pool and 4 workers. The 13 `tests/reset/*` files that earlier steps listed by name were removed from those steps so nothing runs twice; the earlier progression step is renamed "Verify menu scene and legacy-runtime UI boundaries" because only its `tests/scenes` and `tests/legacy-runtime` entries remain. The "PR 284" step and the `run-*-required-tests.mjs` scripts are unchanged. No job or check was added, so the required check count stays the same.
- WHY it changed: CI never calls `npm test`, and the workflow listed only about 20 of the 220 files in `tests/reset` by name, so a broken reset test could merge green. Zac approved this change on 2026-11-26.
- Named exclusions, both still covered:
  - `tests/reset/legacy-unreal-source-fixture.test.ts` calls `process.chdir`, which a worker thread cannot do; it keeps running in its own process in the "PR 284" step (same split as `scripts/verify/run-test-verify.mjs`).
  - `tests/reset/legacy-reset.test.ts` runs as a second command in the new step with a `-t` filter that skips its four tests that read the local-only `mazer-legacy-unreal-restore` fixture ("resumes from the next tile selected during legacy backtracking", "defers overlay rebuild travel until closing the options surface", "routes pause commands through an explicit legacy pause lifecycle contract", "routes menu-time overlay field commits through an explicit legacy flag contract"). The fixture is not in the repository and not on a CI runner; without it they fail with "Missing local mazer-legacy-unreal-restore fixture". The other 33 tests in that file run.
- Rule: a test folder that `npm test` runs is run by CI as a folder, not as a hand-kept file list; any file left out is excluded by name in the workflow with the reason next to it.
- Evidence: on unchanged `origin/main` (79557f80) with `MAZER_LEGACY_UNREAL_RESTORE_ROOT` unset, `vitest run tests/reset --maxWorkers=1` gave 218 files, 2927 passed, 4 failed (the four fixture tests above), 2 skipped, 4 todo, in 790 s, plus one fork-pool "Timeout calling onTaskUpdate" error. The new step's first command (thread pool, 4 workers, two exclusions) gave 216 files, 2882 passed, 0 failed, 2 skipped, 4 todo, no errors, in 268 s and 275 s on two runs; its `legacy-reset.test.ts` command gave 33 passed, 4 skipped. Four workers match the 4 vCPUs of a hosted runner for a public repository. This pull request's own Verify run is the CI proof.
- Status: source only; CI change, no app behaviour change, no deploy needed.
