# CI leftovers: every test file runs once or is excluded with a reason

- WHAT changed: CI now runs every test file under `tests/` exactly once, or the file sits in `config/ci-test-exclusions.json` with a category and a one-line reason. New parallel job `Remaining test folders` runs the 15 folders no step ran before (tests/ai, analysis, config, future-runtime, maze, mazeV2, projections, proof-surfaces, scenes, settings, telemetry, theme, topology-proof, ui, visual) whole. New static check `scripts/verify/check-test-coverage.mjs` (CI step "Check every test file is run once or excluded") fails when a test file is neither run nor excluded, an exclusion is stale, or a file runs twice in one workflow. The five `scripts/verify/run-*-required-tests.mjs` runners now go through `scripts/verify/required-tests-lib.mjs`: they still fail if a listed file is missing, but run only the listed files that no whole-folder run reaches (none today), so required files are no longer run a second time. The "PR 284" step no longer re-runs `legacy-reset` and `legacy-topology-scale-audit` by name; only the process.chdir fixture keeps its own step. `npm test` now calls `scripts/verify/run-test-verify.mjs`, which runs the same folders as CI (the render files are no longer named one by one). `playbook.config.json` `requireTestRegistration.covered` gained the 15 folders.
- WHY it changed: 62 test files (tests/analysis 14, tests/visual 13, and 35 more across 13 folders) were run by no CI step, so a broken one merged green (the same class as the reset and render gaps closed in #727 and #732). The required-coverage runners also ran 23 files twice (4 architecture, 9 render, 10 reset including the two PR #284 files), and `npm test` named render files one by one while CI used the folder.
- Rule: a test folder is run whole by a CI step (so a new test needs no listing) and is added to `requireTestRegistration.covered`; a test that cannot run in CI goes on `config/ci-test-exclusions.json` with a one-line reason; a test that fails on main is excluded with "fails on main: <first error line>", never edited to pass. The check script is the gate. Required-coverage lists assert existence and folder membership instead of running the file again.
- Evidence: method (static, no test run): `node scripts/verify/check-test-coverage.mjs --report` reads every workflow, drops comment lines, collects the `tests/` operands of every `vitest run` / `node --test` command (a folder covers its files, `--exclude` removes a file from that command), adds the runner lists and `npm run` scripts that call `node --test`. Before (origin/main 75e31235): 496 test files, 434 run, 62 not run, 23 run twice. After: 496 test files, 491 run, 5 not run (all excluded with a reason), 0 run twice. Locally the 62 files ran in 36 s (501 tests): 497 passed, 4 failed in 3 files that are now excluded: `tests/playbook-adoption-evidence.test.mjs` (ENOENT on a sibling Playbook checkout file), `tests/playbook-verification-report.test.mjs` (ENOENT on a local ATLAS schema file), `tests/maze/maze-soak.test.ts` (AssertionError: expected false to be true, heap-band check at line 181). Excluded for needing a browser: `tests/analysis/live-auth-persistence-soak.test.mjs`, `tests/ui/dom-settings-primitives.test.ts` (Playwright Chromium; the browser is only installed late in the Verify job). The four `legacy-reset` tests that read the local-only mazer-legacy-unreal-restore C++ tree (21 MB of legacy project source) stay skipped by name in CI: no honest small committed fixture exists. CI job times and logs: see the PR body.
