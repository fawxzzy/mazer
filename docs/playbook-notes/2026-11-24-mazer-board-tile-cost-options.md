- WHAT changed: Follow-up of the #704 finding (iPhone frame cost without the trail painter, about 30 ms of it the board tile layer). A dev-only options page `board-cost-options.html` (root html, not a Vite build input, same pattern as `trail-perf-options.html`) boots the real game at a late level and switches, in place on the same maze, between Today, A "Exact board" (the baked board copied 1:1 at a whole device pixel by `src/render/exactImageBlit.ts` instead of Phaser's resampled draw), B "2x canvas" (canvas backing scale capped at 2, the way the boot path would cap it) and C "Both". The bar shows the measured frame times next to each option, a look line, a live frame meter and the canvas size. `exactImageBlit.ts` is dormant: only the page installs it (`tests/architecture/board-cost-options-dormant.test.ts`), and it falls back to Phaser's own draw whenever the image is not shown exactly 1:1 (`tests/render/exactImageBlit.test.ts`). Probe: `scripts/analysis/board-cost-options-bench.mjs` (layer ablation and in-place option rounds, rAF frame intervals, WebKit or Chromium, captures).
- WHY it changed: WebKit had to be measured before picking a fix. Ranked costs of the frame without the trail painter (WebKit, level 300, 390x844 at 3x, walk / idle ms, medians of 5 interleaved rounds; Today 95 / 77): (1) the board tile image, about 35 / 21 ms: under `roundPixels` Phaser grows every image's destination by half a source pixel (`CanvasRenderer.batchSprite`, `fw += 0.5`), so the 2.75 Mpx device-pixel bake is resampled every frame instead of copied; (2) the trail canvas image, about 34 / 18 ms: a board-sized canvas drawn every frame even with nothing painted, at its own capped scale, so it is resampled too (trail lane, not this page); (3) the floor, about 22 / 20 ms with every display object hidden (clear, compose, game JS); (4) player glow, backdrop, HUD, texts, markers: each within noise. The board bake itself is already cached per hash and re-composed only when the reveal changes, so "redraw only changed tiles" has nothing left to win; the cost is the per-frame draw.
- Rule: A 1:1 device-pixel texture drawn through Phaser canvas with `roundPixels: true` is still resampled (the half-pixel grow); copy it with `drawImage(img, x, y)` at a whole device pixel after `resetTransform()` (never `setTransform(1,0,0,1,0,0)`: `canvasResolution.ts` patches it to multiply by the resolution). Compare options in place on one page and one maze: every `?previewLevel` load builds a different random maze, and a reload-per-option bench on a shared machine swung Today from 90 to 600 ms. Read the in-place 2x cap as WebKit-on-Windows only: its compositor scales the canvas up in software.
- Evidence: In-place option rounds (WebKit, walk / idle ms, median of 5): trail paint off, Today 94 / 85, A 66 / 55, B 86 / 77, C 77 / 67; trail paint on, Today 173 / 127, A 156 / 82, B 165 / 97, C 196 / 96 (C's walk runs ranged 155 to 252, noisy). Ablation (trail paint off): board hidden 60 / 56, trail image hidden 61 / 59, both hidden 26 / 24, everything hidden 22 / 20. Look: same-frame capture of Today vs A differs on 8% of pixels, only along tile edges (max shift half a device pixel; A a hair crisper); B and C are visibly softer on tile edges, stars and text at 3x (crops read side by side). Exact copies counted, zero fallbacks at 3x and at 2x. Nothing was checked on a real iPhone; the WebKit here is a stand-in with software raster and compositing, so the 2x cap may help more on a GPU-composited iPhone than it does here.
