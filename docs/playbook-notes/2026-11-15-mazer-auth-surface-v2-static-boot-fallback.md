# 2026-11-15 Auth Surface v2, PR-A2b (Wave 5C): static "Could not load" fallback when the game bundle never runs

- WHAT changed: `index.html` now carries a hidden static fallback (`#mazer-boot-fallback`: the `MAZER` kicker, `Could not load`, the error line `Check your connection and try again.` and a `Try again` button that reloads) plus a small inline script at the end of `<body>`. When the document has been parsed and deferred scripts have run with no `__MAZER_BOOT_STATUS__`, or when a `<script>` fails to load, the script removes the splash and shows the fallback. Its CSS is inline with plain colours because the CSS bundle may be missing too. The stale `MAZER-UI-034` comment in `MenuScene.ts` (it described a toast failure-code field that no longer exists and sat above an unrelated field) is removed. `tests/reset/loader-handoff.test.ts` now expects two inline scripts, the hand-off script first.
- WHY it changed: PR-A (#594) added the boot-error screen (`src/boot/bootErrorScreen.ts`) for a boot that runs and then throws, but a bundle that never loads left the splash, which removes itself after 8 s and leaves a blank dark page. `index.html` and `MenuScene.ts` are integrator Wave 5C, so this could not ride with PR-A2 (Wave 3B).
- Rule: a boot that runs owns the page through `__MAZER_BOOT_STATUS__`; the static fallback only fires when that status never appears, so the two screens never both show.
- Evidence: `tests/reset/boot-static-fallback.test.ts` (copy pinned to `src/brand/authSurfaceCopy.ts`, the script run against a fake page for no-status, status-present, script-error, other-error and Try-again cases), `npx tsc --noEmit`, the full vitest run.
- Status: source and headless tests only; not checked in a real browser with a blocked bundle, nor on a real phone.
