# 2026-11-16 MAZER-VIS-056 bottom corner stars clear the real display corner

- WHAT changed: new `src/render/displayCornerMask.ts` models Apple's continuous display corner (three cubics; starts 1.53 R along each edge, crosses the diagonal 0.2915 R in). `src/render/edgeCornerAnchor.ts` adds `safeAreaBottom` to the viewport, `hasRoundedBottomCorners` (bottom safe area > 0, else the VIS-054 size band) and `resolveEdgeCornerBottomTipInset`: 20 css px = ceil(continuous R66 diagonal crossing 19.24 + 0.5 px clearance), derived in code from `EDGE_CORNER_DISPLAY_RADIUS_PX`. `src/render/edgeMarkers.ts` places the two bottom corner stars (ids 4, 6) at that inset (`resolveEdgeBottomCornerInset`) and the orbit now takes all four corner positions from the rest layout, so the lap runs through exactly where the stars rest. `MenuScene.resolveLegacyEdgeStations` passes `readMazerViewportGeometry().safeArea.bottom` (a signal, never an offset). Top corners, the header and desktop are unchanged.
- WHY it changed: owner, 2026-11-16: the bottom-left and bottom-right stars are off the screen on the phone, "been an issue more than once". Measured with `scripts/analysis/measure-edge-corner-visibility.mjs` (headless Chromium, DPR 3, touch, iPhone UA, home-screen emulation, safe-area-bottom 34, the real game's draw calls and diffed pixels): (1) in the home-screen app the canvas is the screen minus the status bar, so the 375 x 812 class is 762 tall, below the VIS-054 band (height >= 780): tip inset 0, the star 22.7 / 25.6 / 27.2 px deep in a R55 / R62 / R66 hidden corner (fully hidden). (2) every other phone got the 16 px inset, which is right for a R55 CIRCLE (16.1) but the display is a continuous curve and Pro-class radii run to about 62: 2.9 px hidden at R62, 4.6 px at R66 (about a third of a rest-size star's needle tip). The worst point is the rest corner; the orbit is no worse.
- Rule: derive a corner anchor from the display shape (continuous curve, largest radius you must support) and from a measured signal (the bottom safe area), not from a width/height band. A size band keys on the canvas size, which changes with the display mode (standalone takes the status bar off), so it silently misses devices.
- Failure Mode: "move the constant again" fixes (VIS-044 0 px, VIS-054 16 px) each matched one model (square corner, R55 circle) that was never measured against the real screen shape or the home-screen canvas height. Tests that model the same wrong shape pass while the phone still clips.
- Evidence: `tests/render/edgeCornerRoundedDisplay.test.ts` (new VIS-056 block: 14 viewports incl. home-screen heights x bottom inset 0/34/83 x continuous R48/55/62/66 plus circular R48/R55, rest/75%/100%, the whole orbit lap, and real DPR 3 pixels), `tests/render/displayCornerMask.test.ts`, `tests/render/edgeMarkers.test.ts` (corner gaps, mirror, orbit). Harness results under `tmp/edge-corner-visibility/` (not committed).
- Residual risk: display corner radii are not exposed to the web; R62 for the 16 Pro class is an estimate and R66 is the margin. A phone whose page reports no bottom safe area and is below the band (e.g. an Android with gesture navigation in a tab) keeps the square-corner placement.
- Status: headless only; nothing checked on a real phone.
