# Mazer PWA Offline Shell Reliability Packet

Date: 2026-07-27

## Objective

Ensure a previously loaded production Mazer PWA can restart its immutable application shell while offline, without caching mutable account or progression state.

## Root cause

Mazer boot waits for remote account bootstrap before creating the game. Production service-worker registration previously attached only to a future `window.load` event after that asynchronous work completed. When the document had already reached `complete`, the event could not fire again, so the worker was never registered and the page remained uncontrolled.

The production preflight reproduced that state: an online warm reload had no service-worker controller and the following offline reload fell through to the browser error page.

## Change

- Service-worker lifecycle timing is isolated behind a deterministic runtime contract.
- Registration remains deferred while the document is loading.
- Registration starts immediately when asynchronous boot finishes after `load`.
- Registration start is idempotent.
- Local development continues to unregister Mazer workers and caches.
- The update controller reload guard remains bounded to one reload per ten-second window.

## Persistence boundary

Workbox precaches the versioned application shell generated by the production build. Account, progression, entitlement, and provider data are not introduced into the service-worker cache contract by this packet.

## Verification

- Focused lifecycle tests cover supported/unsupported runtimes, localhost exclusion, pre-load and post-load registration, idempotence, update reload suppression, and safe errors.
- Existing manifest and production-worker source contracts remain explicit.
- Full repository verification and production build must remain green.
- Visible proof requires one online warm install followed by a successful offline reload of the actual Mazer shell.

## Rollback

Revert this packet's source commit and redeploy the preceding known-good Mazer production deployment. The service worker is versioned by the generated build and updates through the existing `autoUpdate` contract.
